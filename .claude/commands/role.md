---
description: Launch a role via numeric command R D T (role · day · task)
argument-hint: "R [D] [T]  — e.g. 1 5 24, or 0 5, or 3"
---

Parse `$ARGUMENTS` as the package's numeric command (see `core/task-protocol.md` → "System of short commands") and dispatch:

- **A single number `N`** → the **architect** role enters day N: read `docs/PROJECT-STATE.md`, `docs/day-<N>-guide.md`, `docs/adr/`, report status. (If the first number is R with more numbers following, see below.)
- **Two numbers `R D`** → role R enters the context of day D with no specific task (review / planning).
- **Three numbers `R D T`** → role R takes task T from `docs/day-<D>-guide.md`: find section "Task T" → the "Prompt for Claude Code" block → execute → run "After completion" → output "Commit".

Digit → role map (single source of truth is `roles.json`; the table below is auto-generated by `sync-roles.py`):

| R | Role | Subagent |
|---|------|----------|
| 0 | Reviewer | reviewer |
| 1 | Developer | developer |
| 2 | QA E2E | qa-e2e |
| 3 | Business Analyst | ba |
| 4 | QA UAT | qa-uat |
| 5 | System Analyst | sa |

Steps:

1. Read R from the first number of `$ARGUMENTS`, match it against the table **from this project's `CLAUDE.md`** (if the digits are reassigned there, the project's table takes priority).
2. Launch the corresponding subagent (Task tool, `subagent_type` = the name from the "Subagent" column) with context: day number, task number, path to the day guide. **On a chained call** (reviewer after developer, architect-status after edits) add to the subagent's context **the previous role's exit report — above all the list of changed files** (`core/task-protocol.md` → "Exit report as handoff input"): scoped roles don't fetch the diff/metrics themselves by default. No report — the subagent flags the gap instead of faking completeness.
   - **Authoritative change-set (the dispatcher runs in the main session).** Before launching **reviewer**, compute the real change-set yourself: `git diff --name-only` (untracked: `git status --porcelain`) and **pass it to the subagent as the authoritative list of changed files**, cross-checking it against the developer's self-declaration — if they diverge, flag this to the reviewer. This closes change-attribution in a repo of any size without relying on the reviewer's own shell (which is prose-scoped to second-model calls and non-mutating checks — ADR-018). This beats the developer's self-declaration (which can omit a file) and a `Glob` tree survey (sees existence, not the fact of change). In prose mode without a Bash dispatcher — floor: developer's self-declaration + `Glob` survey + reviewer's disclaimer.
3. If there's a single number — it's the architect (day entry). If `$ARGUMENTS` doesn't look like a numeric command — execute it as an ordinary prompt from the most fitting role, without inventing a task.

If subagents (`.claude/agents/`) are not set up in the project — just read the needed `roles/<role>.md` and execute in the current session (prose mode: role = prompt).
