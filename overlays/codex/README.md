# overlays/codex/ — enforcement overlay for the Codex CLI runtime

Reproduces the regimen's enforcement layer on **Codex CLI** (OpenAI). Carries **plumbing only** —
the content of the method and roles lives in the shared core (`core/`, `roles/`, …), byte-identical
with the Claude overlay. Structure and form — [ADR-010](../../docs/adr/010-multimodel-core-overlays.md) /
[ADR-011](../../docs/adr/011-process-layer-and-multimodel-build.md); Codex capability map —
[runtime-capability-map](../../docs/evidence/runtime-capability-map.md); sandbox empirics —
[g2-findings](../../docs/evidence/g2-findings.md).

The generator places the contents of this directory at the **root** of the target project: `AGENTS.md` + `.codex/`.

## What's inside

### `AGENTS.md` — entry file (auto-read by Codex), assembled by the generator

Per-harness native entry file (ADR-012): Codex auto-reads `AGENTS.md`. **Carries the CONTENT itself**
(project specifics + routers into `core/`), NOT a pointer "read CLAUDE.md"; a codex project has no
`CLAUDE.md` file. The generator assembles it from two parts: `_agents-header.md` (codex-delta: no slash →
printed `R D T`, roles = `.codex/agents/*.toml` + sandbox tiers, hooks = accountability, memory, second
model) **+ the shared entry body** (`ENTRY-BODY` from the `CLAUDE.md` template — single-sourced for both
runtimes, no drift). The `ROLES-TABLE` markers in the body — the neutral `R → roles/*.md` table is
generated by `sync-roles.py`.

Only the `_agents-header.md` fragment lives in the package (the full `AGENTS.md` appears when a project is generated).

### `.codex/agents/*.toml` — roles as custom Codex agents

Each is a `sandbox_mode` + a `developer_instructions` pointer into the canonical `roles/<role>.md`.
Role tool-scoping is reproduced by the **Codex sandbox tier**:

| Tier | Roles | Codex | Guarantee |
|---|---|---|---|
| read-only | reviewer, auditor | `sandbox_mode="read-only"` | **hardware** (seatbelt, G2-verified) |
| workspace-write | developer, qa-e2e, debugger, devops | `sandbox_mode="workspace-write"` | **hardware** |
| docs-only | ba, qa-uat, sa, architect | `workspace-write` + prose prohibition | **prose** (G2 RED, live agent — the carve-out is structurally unreachable on Codex 0.138.0: cwd is always writable) |
| scratchpad-only | red-team, blue-team, arbiter | `workspace-write` + prose prohibition | **prose** |

Codex collapses Claude Code's three write tiers (read-only / docs-only-Write / code) into a binary
read-only vs. workspace-write; the middle tier ("writes .md but not code") **has no** hardware
equivalent on Codex 0.138.0 → degrades to prose. The guarantee matrix ([core/portability.md](../../core/portability.md))
records this honestly.

### `.codex/skills/*/SKILL.md` — auto-pulled knowledge

Format identical to Claude Code (`name`+`description` frontmatter, body — a pointer into `core/*.md`,
content not duplicated). Universal skills: `debugging`, `code-quality`, `memory`, `spec-driven`.
Discovery — native Codex Agent Skills (repo directory `.codex/skills/` on codex 0.138.0).

### `.codex/hooks.json.example` — hook gates (opt-in)

Analog of `.claude/settings.json.example`. Canonical format = **Claude-Code-compatible `hooks.json`**
(PascalCase events `PostToolUse`/`Stop`/`PreCompact`, a `command` path string, `matcher` tool name —
checked against the real plugin hooks of codex 0.138.0). **KL-7 (live `codex exec`, 6 sessions):** hooks
from user/repo config **do NOT fire** in **headless** mode, even with `--dangerously-bypass-hook-trust`
and a correct schema — working hooks on 0.138.0 = a plugin manifest + interactive TUI trust ("Trust all
and continue"). Plus: `[hooks]` in `config.toml` accepts garbage without error (silent validation
failure). → The regimen's hook gate on Codex **degrades to accountability**; for hard enforcement use
**CI/pre-commit**. Reference scripts `.claude/hooks/` need adaptation for the Codex payload (into `.codex/hooks/`).
Details — [g2-findings → KL-7](../../docs/evidence/g2-findings.md).

## Known degradations (prose instead of hardware)

- **Slash commands** (`/role`, `/panel`, `/kickoff`) — Codex has no custom slash primitive. `R D T`
  remains a printed convention.
- **docs-only / scratchpad-only tiers** — prose (G2 RED, live agent: cwd is always writable, the carve-out is unreachable).
- **Shell confinement is a prose boundary on BOTH runtimes** — since [ADR-018](../../docs/adr/018-second-model-reachability-and-panel-burden.md) every Claude Code role's `tools` DO include Bash (for second-model calls and non-mutating checks; the arbiter's — for the ADR-016 fact-check), with the confinement living in the role prompt; on Codex additionally no per-tool deny exists. "Don't write/edit code" for read-only and docs-only roles stays hardware on Claude Code (no Edit/Write). See the guarantee matrix in [core/portability.md](../../core/portability.md).
- **Hooks** — accountability (KL-7 closed RED: hooks do NOT fire in headless `codex exec`;
  hard gate → CI/pre-commit).

All degradations — in the guarantee matrix [core/portability.md](../../core/portability.md); the
G2/KL-7 empirics — in [g2-findings](../../docs/evidence/g2-findings.md).

**Readiness check (P5):** `python3 regimen-doctor.py` is harness-aware — it detects the wiring (codex),
reports **state, not mere presence**: entry file `AGENTS.md`, agent profiles `.codex/agents/*.toml` with a
valid `sandbox_mode` (read-only/full = hardware), and an honest classification of hooks/docs-only tiers
(= accountability, KL-7/G2). On Claude Code the same doctor reports whether hooks are active or dormant
(`settings.json` vs. `.example`).
